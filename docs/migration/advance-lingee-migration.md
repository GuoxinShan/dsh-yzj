# AI推进迁移说明（dsh MVP → 灵基终态）

> 版本：v1.0 ｜ 日期：2026-08-19
> 出处：0819 14:00 产品方案讨论会（转录已存）+ 《AI推进-产品PRD v2.1》+ [`../spec/ai-advance-design.md`](../spec/ai-advance-design.md)
> 一句话：**MVP 和灵基终态的关系不是「原型 → 移植」，而是「合同 + 证据 → 重建」**。会上已拍板终态承载方式要在灵基侧重新组装（Honeycomb 式底座 + workflow + agent team，非现有插件方式）；因此本仓代码大部分是脚手架，真正交付给终态的是三样：产品合同（概念/判据/schema/交互口径）、机制形状（event loop 的结构）、真机证据（判据精度与噪音水平）。

## 1. 三层拆分：每层的迁移属性不同

| 层 | 内容 | MVP → 灵基 |
|---|---|---|
| **A 产品合同**（不随宿主变） | 推进体 / 意图线程 / 推进回路三概念；事元 + 六态 + 投影折叠数据模型；打扰判据六条 + 静默 + 抑制（spec §13.1–13.3）；门控线（改基准才问、`completed` 只经人、`running` 默认静默，§13.5）；三栏队列 + 时间旅程 + 来源面板信息架构（§7）；时间线永不裁剪（硬要求 ②）；每人看板不同、无上帝视角 | **原样带走**。MVP 存在的意义就是把这层定稿并验证 |
| **B 机制形状**（两边都要有，载体可换） | event-sourced ledger + 投影缓存；意图线程 = 渠道级增量流订阅 + 多事项分发（spec §15）；Work 实时比对 + Dream 每日折叠双节奏；「规则归 host、判断归 LLM」的分界（决策 11）；同源去重 host 强制（决策 19）；completed 后折复盘文档入知识库 + 记忆固化反哺 | **抄形状、换零件**。灵基按此建 Brain / Event Loop |
| **C 宿主承载**（脚手架，全部换掉） | dbt 双表存储；yzj-cli bridge + CLI 轮询 cursor；DSH session / schedule / 确认卡 UI；ui-yzj 第五页签；robot webhook 降级卡片 | **不迁移**。终态：原生推进域服务 + DB、平台事件总线、Brain Scheduler、灵基原生推进页、原生交互卡片 |

组件级映射（承 `../diagrams/advance-5-target-spec.json` footer）：bridge→开放 API 直连 · tool-yzj→推进域服务 · ui-yzj 页签→灵基推进页 · memory-yzj→记忆服务 · harness schedule→Brain Scheduler · robot-yzj→IM 打通层。**映射的判别维度以本文件三层表为准**：组件对得上不代表实现可搬，先问它属于 A/B/C 哪层。

## 2. 合同清单（终态必须逐条照抄的条款）

1. **三概念**：推进体（用户语言「发起一个推进」）/ 意图线程（订阅的数据渠道，可多条；事元 = 线程上被采纳的 event）/ 推进回路（回到发起者验收，AI 辅助、人拍板）。**v1.8 术语修订（2026-08-20 用户拍板）**：「意图线程」对外改称「**上下文来源**」——意图属于事项（意图体），渠道只是事项的上下文来源；合同语义不变（渠道级增量订阅 + 多事项分发），MVP 载体改名 `yzj_advance_sources`。
2. **数据模型**：事项 7 字段投影 + append-only 事元流（时间/来源类型/变化类型/摘要/变化内容 原值→新值/引用/操作者）；投影是折叠缓存，流是事实；变更唯一通道 = feed 一条事元（无 update/delete，决策 4）。
3. **状态机**：六态 + 合法流转表（spec §2）；`completed` 只经用户验收；阶段变化本身是一条事元。
4. **打扰契约**：六条打扰判据 / 静默判据 / 三条抑制（§13.1–13.3）；看板队列是「让人决定」的面、写门禁是「让人批准」的面，不叠加（§13 开篇）。
5. **写门控线**：纯追加与阶段变化静默；`goal/metrics/targetDate/assignee` 改基准才问；用户直写（judge 五动词、一句话喂入）不经门禁（D9）。
6. **看板信息架构**：三栏队列（待我决定/待我验收/我关注的推进）+ 详情（指标卡/当前目标/阶段化决策区/三色时间旅程+来源跳转）+ 信息来源面板；「不建立新文件库，解释工作事实为什么支持或不支持目标」。
7. **知识出口**：completed 后折复盘文档（目标演化/关键决策/偏差证据链）入知识库；纪要四段结构（目标/内容/共识/下一步）。
8. **命名口径**：产品名「AI 推进」，中性、双向（上对下对齐 + 下对上反馈），不用「参谋部」（0819 会议拍板）。

## 3. 断层点（迁移时最容易做错的五处）

| # | 断层 | 禁止事项 / 正确姿势 |
|---|---|---|
| 1 | **发现通道是宿主限制**：MVP 用 CLI 轮询 + cursor 是因为机器人 WS 收不到全量群消息（spec §14.1） | 合同表述为「意图线程 = 渠道级增量事件流的订阅」；灵基直接订事件总线。**不要把轮询 cursor 逻辑当合同抄走** |
| 2 | **意图线程订阅的承载**：MVP 存 host storage-domain（spec §15，决策 20），因为 demo 存储不便扩列 | 终态订阅是事项聚合的一部分（原生关系表）；storage-domain 只是 demo 落位 |
| 3 | **确认卡是借的**：MVP 用 DSH `tools/pre-execute` 卡片 | 门控线规则表（§13.5）原样搬；卡片 UI 灵基自建 |
| 4 | **策略选择的结构**：MVP 在决策请求事元的 `变化内容` 里用文本行约定备选（spec §15.4，决策 23） | 终态应原生结构化（备选数组 + 影响复述），MVP 文本约定是降级证据不是设计 |
| 5 | **Agent 形态不承诺**：终态用单 agent 还是 agent team / workflow / 图谱底座，是灵基实现自由（0819 会议说话人 3） | 合同只约束机制形状（B 层）与教学纪律（INSPECT_DISCIPLINE 语义），不约束编排方式 |

## 4. MVP 验证清单（证据落点）

**能证明、正在证明的**（证据记 [`../status/gap-analysis.md`](../status/gap-analysis.md) §24.x）：

| 验证目标 | 对应合同条款 | 证据现状 |
|---|---|---|
| 打扰判据精度（静默/提示边界人是否可忍受） | §2-4 打扰契约 | dsh-2 真机巡检（§24.4）；**830 真数据实验已跑（§24.6）：巡检 16 条候选只静默喂 1 条、零打扰卡、噪音全拒——静默/打扰边界成立** |
| 事元 schema 表达力（时间旅程+复盘+沉淀够不够） | §2-2 数据模型 | 六态闭环 E2E、feed 旅程 E2E 已过；**830 实验补真机证据（§24.6）：立项+目标更新+回放+巡检 feed 五类事元完整呈现；发现 refs 去重粒度误伤合法引用（待拍板）**；④期复盘出口待做 |
| 人机分工交互（人是否真的只剩判断） | §2-5/6 门控+看板 | 门控线收窄已真机验证（§24.3） |
| 意图线程订阅闭环（多源装配→事元→建议→拍板回流） | §2-1 三概念 | **schema 刚补（spec §15），未实现未验证——当前最高优先级缺口** |

**证明不了的（不要在 MVP 里硬试）**：组织级多用户与权限（MVP 单人 CLI 凭据）；「控节奏」（多人上下文/节奏差异，0819 会议课题）；数据类工作现场自动读数（无业务数据源，数据事元只能手工喂）；事件总线级实时性（MVP 是轮询 + 被召唤）。

## 5. 取舍原则：往合同里存钱，不给脚手架镀金

每个新任务先问：完善合同/攒证据（A/B 层），还是给注定扔掉的 C 层加功能？

- **存钱**：意图线程订阅落地与验证；策略选择结构化；830 真数据判据精度实验；④期复盘出口；给领导/灵基的产品模块关系图与故事线（用合同语言画，不画 DSH 组件——受众不认 bridge/tool-yzj）。
- **镀金（够用就停）**：headless routine 打磨、robot 卡片美化、DSH 面板锦上添花。
