## 0. 北极星

**一个云之家群 = 一个群房间 + N 条话题会话。群房间是 IM 桥（读群、轻发送、长话题），话题会话是 agent 对话（工作发生地）。每个视图只有一个发送动词。**

DSH 仍是唯一家园（D1 精神不变）：群房间和话题都住在 DSH 里，云之家仍是投递面与召唤面。被取代的不是「家园在 DSH」，而是「一个群挤进一条会话、四类消息共一条流」。

---

## 1. 为什么推翻融合一条流（决策依据，第一性）

五条公理：

1. **两种对话物理性质不同**：群聊公开、低密度、中断驱动、说话即全部效果；agent 会话私密、高密度（长回复 + 工具卡）、专注驱动、有副作用。压进一条流互相摧毁节奏。
2. **可见性边界跟容器不跟条目**：同一条流里 ①② 公开、③④ 私密，用户要逐条判断「别人看得到吗」，看错即泄密。容器级（这个视图=公开，那个=私密）一眼即懂。
3. **一个输入框一个动词**：双发送按钮或「助手|本群」模式切换都是在收认知税，且模式残留误发进群踩中不可撤回的高风险侧。
4. **空间 : 任务 = 1 : N**：群活几个月，一个 agent 任务活几小时。1:1 绑死两者寿命 → mega-session、上下文爆炸、找不到历史任务。
5. **群是多人的，任务是并发的**（决定性）：张三让机器人排期、李四让它查 bug，1:1 意味着所有人的任务挤同一条 session 时间线，人找不到、模型上下文互相污染。

历史订正：robot-channel §3.6 S1 最初就是 per-thread 多会话（对齐 Claude Tag），v1.8 收成 1:1 的理由是「工作藏在隐藏 `yzj-robot-*` 里看不见」。**1:1 是对『隐藏』的过度矫正——病根在不可见，不在多条。** 本法以「话题必须在群房间可见列出」治本（R4 不变量 3），锚定机制照抄 S1。

## 3. 对象模型

只读 docs/ 的下一个 agent 必须能凭本节重建对象。

```
GroupRoom                                  // 每群一个
  yzjConversationId: string                // 云之家 groupId（与 CLI 同 ID 空间）——主键
  hostSessionId:     string                // 承载 session（yzj-home-<slug>，沿用既有绑定 id）
  roomLog:           YzjBoundMessageLog    // 群时间线，语义沿用 transcript §3（按群索引）

TopicSession                               // 每群 0..N 条
  dshSessionId:      string                // yzj-topic-<slug>-<n|rootMsgId8>
  yzjConversationId: string                // 属于哪个群
  anchor:                                  // 从哪长出来
    | { kind: 'yzj';     rootMsgId: string; from: string; excerpt: string; sentAt: number }
    | { kind: 'dsh';     rootMsgId?: string }      // DSH「交给助手」（有锚）或群房间内直接新建（无锚）
    | { kind: 'handoff'; fromSessionId: string }   // 丢进群交接来
  title:             string                // 默认锚消息摘要，可改名

TopicAnchorIndex                           // S1 复活
  (yzjConversationId, rootMsgId) → dshSessionId    // 顶层 @ 与「交给助手」写入
  机器人出站 msgId → dshSessionId                   // 出站登记，回复链续接靠它归位
```

不变量：

1. 一群至多一个群房间；话题 0..N，同群并存。
2. 同一 `(yzjConversationId, rootMsgId)` 至多一条话题：同根重复 @ / 重复「交给助手」= focus 已有话题。
3. **话题必须可见**：群房间列出本群全部话题；禁止任何形式的隐藏平行 session（D10 精神，治 S1 当年被砍的病）。
4. 群房间时间线不写 `Session.append`（T1）；话题会话是官方 session。
5. 顶层新 @（新 rootMsgId）= 新话题，不做「续最近一条」启发式（可预测性 > 便利）。
6. 持久化：GroupRoom 映射沿用 `yzj_home_bindings` domain（语义从「群↔会话」变为「群↔群房间」）；TopicAnchorIndex 新 domain，重启后锚定仍在。
7. 群房间宿主必须非 blank：打开时补一次已关闭空 turn + `session/title`（R14）。blank「新会话」点走会藏，但没有对话 tab，工作台挂不上。房间不 attach「云之家」（R20）。话题官方列表标题 = `话题标题 · 群名`。

## 4. 两种视图

### 4.1 群房间（IM 桥）

> UI 标签说明（v1.3，2026-08-18）：视图的可见名称是「群聊」（单聊房间「私聊」），「群房间」保留为设计概念名。view tab、pill、提示文案统一用前者。

- 时间线 = roomLog 全量投影：他人消息、本人消息（云之家发的 ① `isSelf` 与 DSH 发的 ②，渲染同为「我」）、助手帖子（R9，带话题回链）。回填（T9）、去重（T8）、非文本（transcript §3.3）全部沿用。身份和媒体复用悬浮窗渲染器（头像、`MessageBody`、`[握手]` 表情、图文/文件经 `file-data` 代理、回复引用）；**IM 两侧都有可见气泡**（官方 Chat 只给用户一侧上色，不能照搬）：自己靠右、`22px`、`--dsw-specific-bubble`；他人 / 助手靠左同圆角，底 `--dsw-alias-interactive-bg-hover-solid`（浅色 `bg-layer-*` 与画布同色，见 pitfall-023）。同人连发合并；日期分隔线。顶部「加载更早消息」再回填一页。人名空时走通讯录，禁止「群消息」占位。
- 行操作（回复 / 交给助手）hover 才出，16px 文字链。已是话题根：气泡内嵌「N 条回复」chip，不再显示「交给助手」。助手文件帖子在气泡内出产物卡。
- 本群话题主入口是右侧话题抽屉（header「话题 N」开关；v1.1 改写原侧栏树）。时间线不再铺顶部话题列表 chips（气泡内嵌回复 chip 除外，见 §9.1）。
- composer：唯一动词**发进群**（乐观 ②、`/yzj` 直写、无 user-turn、无确认卡——transcript §6.1 时序沿用）。占住 `conversation.composer` chain 以藏官方输入条，**可见面 portal 进时间线列**（不压会话列表、不铺到话题抽屉底下）。脸跟官方 InputBar：圆角卡片 + 底部工具行 + **圆形发送**（`aria-label` 发进群，不在右下角挂「发进群」字）。placeholder「发到 群名…」。工具条接 CLI send 全集（回复条、表情、图、文件、@ / @all）。**没有** dock「发进群」、没有「发给助手」、没有模型选择；要用助手就长话题。**界面不朗读发送语义**。

### 4.2 话题会话（agent 对话）

- **落官方 Chat，不是 IM 工作台**（R19 / R22）：从官方侧栏「云之家」点进话题，必须看见 ③④ + 工具卡 + 确认卡。tab ring 打开时点「对话」并藏「群聊」tab；禁止让持久化 `view=yzj-home` 把话题画成群聊三栏。
- 官方 chat 形态：③④ + 工具卡 + 确认卡（GUI 卡机制沿用）。
- 回群入口叠在官方 composer dock 上（`conversation.input.dock`）：与 InputBar 卡同一列宽（`--dsh-composer-card-max-width` + 两侧 clearance），22px 圆角、同一套 input 表面 token，坐在输入卡正上方，不进标题行。文案只写「回群聊」（单聊「回私聊」）；锚摘要作次行省略，不写「群消息锚点 / 点这里」。**这是话题里唯一回群入口**。官方发送 = 问助手。
- 回复链续进来的群消息：作为日志投影节点插入话题流（标「XX · 从云之家回复链续入」），同时它也出现在群房间时间线（同一日志行，两个容器投影）。
- composer：唯一动词**问助手**（官方输入条本身，dock 不再挂「下方发送 = 问助手」说明书）。召唤窗口注入沿用 T4/T5（窗口取自 roomLog 近窗，`formatSummonWindow` 同一函数）。**窗口必须带 `groupId`、每行 `msgId`、话题则带锚点 `msgId`**，否则模型无法对群发/回复。T5 查会话必须同时打房间表与话题表（`getBySession` 只认 `yzj-home-*`，话题会落空——pitfall-027）；首轮 assemble 可能还没有 user/message（`none`），不得当成「未召唤」丢掉窗口。
- **job-done 投递（R26）**：本轮 idle 后，host 把最后一条助手正文做成有界总结，以 CLI 本人身份（② `dsh-send`）回复锚点；产物随附。群房间时间线能看见这条回复（及跟发的文件）。这不是「每条助手气泡都回群」。
- agent **另起**发群：`WRITE_SPECS` 确认卡（标准），放行后投回群房间/回复链，话题内标「已投递」。本轮若已走这条，R26 不再自动投，避免双帖。

### 4.3 未绑定私聊

不变（D7）：无群流、单一发送、「丢进群」（D8：默认摘要 + 确认卡）。引用只走 `@` 候选源，不提供拖入 chip（R23）。普通 DSH session 与未绑定私聊同样走官方 Chat：view-ring 点「对话」、IM 壳不画（R22）。binding 表里若残留「某普通 session = 房间」也不得把它提升成群聊视图。

## 5. 四入口时序

| 入口 | 时序 |
|---|---|
| DSH「交给助手」 | 群房间消息 → 查锚定表 → 无则 create 话题（锚=该消息）+ 写锚定表 → **抽屉透镜打开（时间线仍在场）**；开话题本身不启轮。第一次问助手才注入锚 + 近窗：抽屉「问助手」`inject(formatSummonWindow)` 再 `followup`；官方 Chat 走 T5 `yzj-bound-window`（同一函数）。「原生会话 ↗」才 focus 官方 Chat |
| 云之家顶层 @机器人 | 写 ① 进 roomLog → 查 `(groupId, msgId)` → 无则建话题 → `formatSummonWindow` + `agent.inject` → `followup` 进该话题 session（robot-yzj `resolveSession` 改指话题，不再指单一绑定会话） |

| 丢进群（私聊 → 群） | D8 不变：勾选摘要 → 确认卡 → 群房间落 ② → 着陆群房间；可选「继续在新话题工作」（anchor kind `handoff`） |

## 7. 验收口径（实现对照用）

1. 打开群 A 两次 → 同一个群房间；工作台会话列表标题 = 群名；官方侧栏「云之家」分组**不**出现该群聊行（R20）。
2. 群房间发送：立刻 ② 气泡、无确认卡、不触发模型；输入框没有第二个动词。
3. 群房间消息「交给助手」→ 新话题并在抽屉打开（时间线仍在场）；对同一条消息再点 → 抽屉重开已有话题，不新建。
4. 云之家顶层 @机器人 → 群房间话题列表出现新话题；回复链带 @ 续 → 进同一话题，不新建。
5. 话题里 agent 提议发群 → 标准确认卡；放行后群房间出现助手帖子，带「来自话题 X」回链；话题内标「已投递」。
5b. （v1.10 / R26）DSH 话题里问助手、轮次结束后：云之家该条锚点的回复链出现一条总结（本人身份），不是整轮工具过程；有 `write`/`edit` 产物则随附（图在回复里，其它文件跟发在群里）。plugin 入站 / 已调 `yzj_im_message_send` / 无真实锚点不投。
6. 群侧发起、无人聚焦 DSH → 群内建议卡（@机器人 确认 N）裁决，与 GUI 卡同一 writeId。
7. `robot_notify` / `robot_continue` 在 `yzj-topic-*` 会话上同样入闸（R10；pitfall-012 回归）。
8. 未绑定私聊：单一发送；丢进群默认摘要 + 确认卡，着陆群房间。
9. 无隐藏话题：群房间话题列表 = 该群全部话题；不存在列表外的 `yzj-topic-*` / `yzj-robot-*` 家园。
10. 退役面干净：无「群工作」旁路 tab、无 dock 发进群、无双意图 composer、无面板第二 IM composer。
11. 侧栏脚「群空间」树：已打开的群房间为父行，其话题缩进挂在下面；父行可折叠；点行 focus 对应 session。未打开的最近群也可出现在树里，「加载更多会话」翻页，点开 = 打开群房间。
12. 群房间时间线能认出真人名+头像（不是「群消息」）；自己靠右、他人靠左；表情/图片/文件可读；「加载更早消息」能翻到回填窗口以外。hover 出「回复 / 交给助手」。

## 9. v1.1 增补：云之家工作台（已拍板 2026-08-17 下午）

> 缘起：用户对 R12 侧栏树提出三连反馈——「UI 要更精致」「群空间应有独立子页承载而非侧栏铺开」「群与对话之间要一层会话/话题列表」，随后确认导航范式为「IM 统一入口」；拍板后追加修正「话题应是对话中很轻的东西」——话题面从整面页签改为右侧抽屉（Slack 线程式）。可交互原型（Cursor canvas `group-room-three-column.canvas.tsx`）走查通过后拍板六项（§9.6）。本节是 R15–R21 的展开；与 v1.0 冲突处以本节为准（冲突点已在原条款内标注）。

### 9.1 三栏结构

```
① 官方侧栏（不动）                 ② 工作台中栏（域列表）           ③ 内容栏
   DSH 会话（含云之家 workspace 分组）   对话：会话列表（群+单聊混排）      时间线常驻 + 发进群 composer
   ┌ 侧栏脚「云之家」入口块 ┐            待办：任务列表（库切换器）          ┌ 话题抽屉（右侧轻栏，可关）┐
   │ 对话 / 待办 / 日程     │            日程：今日列表                    │ 列表态：话题卡         │
   │ 知识库                 │            知识库：按库分组文档               │ 透镜态：锚点条+气泡+问助手│
   │ 机器人通道 · 状态行    │                                               └（header「话题 N」开关）─┘
   └──────────────────────┘                                              其余域 = 详情面（字段 + 跨域动作）
```

- 载体不变：入口块 = `sidebar.footer.action`（原树的槽位原地重画）；工作台 = 既有 `conversation.view` 子页内部自排两栏。不 fork harness。**视图根必须带 `data-conversation-composer-overlay`**（harness 官方有界视图契约，viewArea 才有界、三栏各自内部滚动；pitfall-020）。时间线打开即触底：跟随判定以 wheel/touch 为用户转向信号，程序化 scrollIntoView 不许脱离跟随（pitfall-020）。
- **对话域点击不堵 RPC**：侧栏脚「对话」先 `setWorkbenchDomain('im')`。已在 `yzj-home-*` 上只切域；否则立刻 focus 模块缓存的上次房间（`rememberImSeat`，打开房间 / 话题绑定 / dock 预取 `home-nav` 写入）。`home-open` 只在后台补座位，**不得**挡住第一帧。无缓存才走 `home-nav` / `im group recent`。会话列 `convListHold` 仍跨 `conversation.view` 重挂保左栏。
- **发送条只跟对话域**：群聊「发进群」与话题官方「问助手」只在工作台域 = 对话（或官方 Chat 话题页）出现。待办 / 日程 / 知识库不挂任何 composer——房间 takeover 仍占住官方条以免露出发给助手，但组件画 `null` 并收起 `data-composer-seat`。时间线卸掉时禁止把发进群回退到官方座位（否则待办底下会冒出发送卡）。
- 对话域会话列表 = `im group recent`（原生混排群/单聊，按时间序）；滑到列底自动翻下一页（列未填满视口也会继续取）。单聊行点开即聊（R17），无话题抽屉。绑定房间不在 recent 首页时由 host 分页回填真实群名（禁止「群聊」鬼影行）。
- **话题抽屉是「对话中很轻的东西」**：时间线永远是主体、永不被顶走；抽屉固定窄栏（≈340px）、随手可关（×）；列表态 ⇄ 透镜态在抽屉内切换（‹ 返回）；抽屉底部「问助手」轻输入。反跳（L6）时抽屉不关——左时间线高亮定位、右透镜保持，两边同屏对照。锚点卡摘要 clamp 两行，不 dump 原文。
- 精致度基线（P1 验收对照）：同人连发合并（首条带头像名，后续缩进）、日期分隔线、自己 8/2/8/8 右气泡 / 他人 2/8/8/8 左气泡 / 助手左描边、行操作 hover 16px 文字链、助手产物卡（类型徽标 + 文件名 + 落库指引）、话题入口 = 气泡内嵌「N 条回复」chip（取代行尾文字链）。**机器人身份**：`BOT-` 前缀 openId 标「机器人」（联系人目录查不到机器人，禁止渲染 openId 尾巴）；**机器人长帖折叠**：超 240 字的机器人/助手文本帖收 4 行 +「展开全文」（IM 流不是 markdown 画布）。

### 9.2 联动规则 L1–L6（话题 × 会话列表）

合并发生在客户端：中栏把 recent 列表与 `ctx.yzjTopics` 快照按 groupId 拼接。`TopicRecord` 有 `lastActivity`（P0）和 `status`（P3：`running` / `confirm` / `done`）。write-gate 在 `yzj-topic-*` pending/approved 写时把该话题打成 `confirm`，交付或取消后按 L5 回落 `running`。

| # | 规则 | 行为 |
|---|---|---|
| L1 | 上浮 | 群行时间与摘要 = max(最新群消息, 最新话题活动)；话题动态带「话题·标题」前缀 |
| L2 | 徽标分级 | accent 数字 = 待确认话题数（`status=confirm`）＞ 细点 = 有进行中 ＞ 全完成无标；**不是未读数** |
| L3 | 就地成话题 | 时间线「交给助手」→ 建话题并在右侧抽屉打开（时间线不被顶走）；该消息行操作立刻变「N 条回复」chip（幂等，二次点击 = 抽屉重开该话题） |
| L4 | 双入口一会话 | 话题在官方侧栏照常列出（不隐藏不复制）；两个入口进同一会话，默认投影不同（R19） |
| L5 | 交付回落 | 话题内「发进群」过确认卡后成为真实群消息：群行摘要回普通消息、话题降级、徽标随之降 |
| L6 | 全量反跳 | 话题内一切群消息引用可点、跳回时间线定位高亮：头部锚点条、过程中引用的群消息卡（记 msgId + 摘要快照）、交付回执「已发进群 · 查看群消息」；目标不在已加载窗口先 backfill 再定位。与内嵌 chip 构成双向闭环 |

群行点击**永远落时间线、抽屉不自动弹开**（拍板 #5）：落点可预测，话题动态靠 L1 前缀 + L2 徽标引导。

### 9.3 话题双投影（R19 展开）

- **IM 透镜**（群内话题抽屉）：气泡流、轻交互、锚点条、引用卡、回执；抽屉 header「原生会话 ↗」。
- **原生视图**（官方 conversation）：完整轨迹 / 工具卡 / 确认卡 / 全量 composer；回群聊叠在官方 composer dock（§4.2）。
- 两个投影读同一份 session 事件日志；跳转 = 官方 focus API，零新机制。

### 9.4 云之家 Host Workspace（R20 展开）

- 固定专属目录作为全部 yzj 会话的 `meta.cwd`（目录位置 = 实现决策，落地记 gap）——房间和话题都建在这里，避免 `process.cwd()` 污染编码工作区。启动时 ensure「云之家」workspace（`ctx.workspaceRegistry`）。
- **attach 只对话题**（`yzj-topic-*`）。群房间宿主（`yzj-home-*`）即使 cwd 落在同一目录，也**不** `attachSession`。harness 侧栏按 workspace 成员分组：只有被 attach 的会话出现在「云之家」分类下。
- **存量清扫**：插件 ensure workspace 时 `detachSession` 摘掉已挂上的 `yzj-home-*`（v1.1 误 attach 的房间）。不归档、不删 session 文件、不动话题。打开工作台或重启 GUI 后旧房间从该分组消失。
- 效果：官方侧栏「云之家」= 群聊长出的 agent 工作（话题）；群聊本身只活在工作台对话域（R15）。v1.1 曾 attach 全部 yzj 会话，把 IM 房间也挂进该分类——v1.4 纠正。
- 不用归档藏房间（pitfall-021：归档单向，归档后打不开）。正确手段是根本不 attach；已挂上的用 detach 撤回成员资格。
