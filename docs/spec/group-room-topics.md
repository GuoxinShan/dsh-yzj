## 0. 北极星

**一个云之家群 = 一个群房间 + N 条话题会话。群房间是 IM 桥（读群、轻发送、长话题），话题会话是 agent 对话（工作发生地）。每个视图只有一个发送动词。**

DSH 仍是唯一家园（D1 精神不变）：群房间和话题都住在 DSH 里，云之家仍是投递面与召唤面。被取代的不是「家园在 DSH」，而是「一个群挤进一条会话、四类消息共一条流」。

---

## 1. 为什么推翻融合一条流（决策依据，第一性）

五条公理：

1. **两种对话物理性质不同**：群聊公开、低密度、中断驱动、说话即全部效果；agent 会话私密、高密度（长回复 + 工具卡）、专注驱动、有副作用。压进一条流互相摧毁节奏。
2. **可见性边界跟容器不跟条目**：同一条流里 ①② 公开、③④ 私密，用户要逐条判断「别人看得到吗」，看错即泄密。容器级（这个视图=公开，那个=私密）一眼即懂。
3. **一个输入框一个动词**：双发送按钮或「助手|本群」模式切换都是在收认知税，且模式残留误发进群踩中不可撤回的高风险侧。
4. **空间 : 任务 = 1 : N**：群活几个月，一个 agent 任务活几小时。1:1 绑死两者寿命 → mega-session、上下文爆炸、找不到历史任务。
5. **群是多人的，任务是并发的**（决定性）：张三让机器人排期、李四让它查 bug，1:1 意味着所有人的任务挤同一条 session 时间线，人找不到、模型上下文互相污染。

历史订正：robot-channel §3.6 S1 最初就是 per-thread 多会话（对齐 Claude Tag），v1.8 收成 1:1 的理由是「工作藏在隐藏 `yzj-robot-*` 里看不见」。**1:1 是对『隐藏』的过度矫正——病根在不可见，不在多条。** 本法以「话题必须在群房间可见列出」治本（R4 不变量 3），锚定机制照抄 S1。

## 3. 对象模型

只读 docs/ 的下一个 agent 必须能凭本节重建对象。

```
GroupRoom                                  // 每群一个
  yzjConversationId: string                // 云之家 groupId（与 CLI 同 ID 空间）——主键
  hostSessionId:     string                // 承载 session（yzj-home-<slug>，沿用既有绑定 id）
  roomLog:           YzjBoundMessageLog    // 群时间线，语义沿用 transcript §3（按群索引）

TopicSession                               // 每群 0..N 条
  dshSessionId:      string                // yzj-topic-<slug>-<n|rootMsgId8>
  yzjConversationId: string                // 属于哪个群
  anchor:                                  // 从哪长出来
    | { kind: 'yzj';     rootMsgId: string; from: string; excerpt: string; sentAt: number }
    | { kind: 'dsh';     rootMsgId?: string }      // DSH「交给助手」（有锚）或群房间内直接新建（无锚）
    | { kind: 'handoff'; fromSessionId: string }   // 丢进群交接来
  title:             string                // 默认锚消息摘要，可改名

TopicAnchorIndex                           // S1 复活
  (yzjConversationId, rootMsgId) → dshSessionId    // 顶层 @ 与「交给助手」写入
  机器人出站 msgId → dshSessionId                   // 出站登记，回复链续接靠它归位
```

不变量：

1. 一群至多一个群房间；话题 0..N，同群并存。
2. 同一 `(yzjConversationId, rootMsgId)` 至多一条话题：同根重复 @ / 重复「交给助手」= focus 已有话题。
3. **话题必须可见**：群房间列出本群全部话题；禁止任何形式的隐藏平行 session（D10 精神，治 S1 当年被砍的病）。
4. 群房间时间线不写 `Session.append`（T1）；话题会话是官方 session。
5. 顶层新 @（新 rootMsgId）= 新话题，不做「续最近一条」启发式（可预测性 > 便利）。
6. 持久化：GroupRoom 映射沿用 `yzj_home_bindings` domain（语义从「群↔会话」变为「群↔群房间」）；TopicAnchorIndex 新 domain，重启后锚定仍在。
7. 群房间宿主 session 必须非 blank：打开时补一次已关闭空 turn + `session/title`（R14），官方列表标题 = 群名。话题官方列表标题 = `群名 · 话题标题`。（v1.1）IM 导航在工作台对话域（R15）；全部 yzj 会话**进「云之家」Host Workspace**（R20，改写本条原「不进 Host Workspace」）。

## 4. 两种视图

### 4.1 群房间（IM 桥）

- 时间线 = roomLog 全量投影：他人消息、本人消息（云之家发的 ① `isSelf` 与 DSH 发的 ②，渲染同为「我」）、助手帖子（R9，带话题回链）。回填（T9）、去重（T8）、非文本（transcript §3.3）全部沿用。身份和媒体复用悬浮窗渲染器（头像、`MessageBody`、`[握手]` 表情、图文/文件经 `file-data` 代理、回复引用）；**布局跟 canvas / §9.1**：自己靠右气泡（8/2/8/8，meta「我 · 时」）、他人靠左（2/8/8/8，头像 + 名 · 时）、助手帖子左边强调；同人连发合并；日期分隔线。顶部「加载更早消息」再回填一页。人名空时走通讯录，禁止「群消息」占位。
- 行操作（回复 / 交给助手）hover 才出，16px 文字链。已是话题根：气泡内嵌「N 条回复」chip，不再显示「交给助手」。助手文件帖子在气泡内出产物卡。
- 本群话题主入口是右侧话题抽屉（header「话题 N」开关；v1.1 改写原侧栏树）。时间线不再铺顶部话题列表 chips（气泡内嵌回复 chip 除外，见 §9.1）。
- composer：唯一动词**发进群**（乐观 ②、`/yzj` 直写、无 user-turn、无确认卡——transcript §6.1 时序沿用）。占住 `conversation.composer` chain，placeholder「发进 群名…」，主按钮就是「发进群」；工具条接 CLI send 全集（回复条、表情、图、文件、@ / @all）。**没有**「发给助手」、没有模型选择；要用助手就长话题。

### 4.2 话题会话（agent 对话）

- 官方 chat 形态：③④ + 工具卡 + 确认卡（GUI 卡机制沿用）。
- 头部：锚点卡（锚消息摘要 + 回跳群房间），叠在官方 composer dock 上；官方发送 = 问助手。
- 回复链续进来的群消息：作为日志投影节点插入话题流（标「XX · 从云之家回复链续入」），同时它也出现在群房间时间线（同一日志行，两个容器投影）。
- composer：唯一动词**问助手**。召唤窗口注入沿用 T4/T5（窗口取自 roomLog 近窗，`formatSummonWindow` 同一函数）。**窗口必须带 `groupId`、每行 `msgId`、话题则带锚点 `msgId`**，否则模型无法对群发/回复。
- agent 要发群：`WRITE_SPECS` 确认卡（标准），放行后投回群房间/回复链，话题内标「已投递」。

### 4.3 未绑定私聊

不变（D7）：无群流、单一发送、可拉引用 chip、「丢进群」（D8：默认摘要 + 确认卡）。

| DSH「交给助手」 | 群房间消息 → 查锚定表 → 无则 create 话题（锚=该消息）+ 写锚定表 → **抽屉透镜打开（时间线仍在场）**；抽屉「原生会话 ↗」才 focus 官方 Chat；注入锚消息 + 近窗 |
| 云之家顶层 @机器人 | 写 ① 进 roomLog → 查 `(groupId, msgId)` → 无则建话题 → `formatSummonWindow` + `agent.inject` → `followup` 进该话题 session（robot-yzj `resolveSession` 改指话题，不再指单一绑定会话） |
| 回复链带 @ 续接 | 解析 rootMsgId（入站 `replyRootMsgId`，缺则经出站登记的机器人 msgId 归位）→ 命中话题 → 写 ① + 投影进话题 + followup 续；未命中（回复的不是机器人链）→ 按顶层处理 |
| 丢进群（私聊 → 群） | D8 不变：勾选摘要 → 确认卡 → 群房间落 ② → 着陆群房间；可选「继续在新话题工作」（anchor kind `handoff`） |

## 7. 验收口径（实现对照用）

1. 打开群 A 两次 → 同一个群房间；侧栏标题 = 群名。
2. 群房间发送：立刻 ② 气泡、无确认卡、不触发模型；输入框没有第二个动词。
3. 群房间消息「交给助手」→ 新话题并在抽屉打开（时间线仍在场）；对同一条消息再点 → 抽屉重开已有话题，不新建。
4. 云之家顶层 @机器人 → 群房间话题列表出现新话题；回复链带 @ 续 → 进同一话题，不新建。
5. 话题里 agent 提议发群 → 标准确认卡；放行后群房间出现助手帖子，带「来自话题 X」回链；话题内标「已投递」。
6. 群侧发起、无人聚焦 DSH → 群内建议卡（@机器人 确认 N）裁决，与 GUI 卡同一 writeId。
7. `robot_notify` / `robot_continue` 在 `yzj-topic-*` 会话上同样入闸（R10；pitfall-012 回归）。
8. 未绑定私聊：单一发送；丢进群默认摘要 + 确认卡，着陆群房间。
9. 无隐藏话题：群房间话题列表 = 该群全部话题；不存在列表外的 `yzj-topic-*` / `yzj-robot-*` 家园。
10. 退役面干净：无「群工作」旁路 tab、无 dock 发进群、无双意图 composer、无面板第二 IM composer。
11. 侧栏脚「群空间」树：已打开的群房间为父行，其话题缩进挂在下面；父行可折叠；点行 focus 对应 session。未打开的最近群也可出现在树里，「加载更多会话」翻页，点开 = 打开群房间。
12. 群房间时间线能认出真人名+头像（不是「群消息」）；自己靠右、他人靠左；表情/图片/文件可读；「加载更早消息」能翻到回填窗口以外。hover 出「回复 / 交给助手」。

## 8. 本版明确不做

- 完整 IM 客户端：表情回应、已读回执、撤回、转发、名片、群管理（R7 红线；CLI 无对应命令，不造假）。
- 免 @ / ambient / 顶层无 @ 自动响应（D11 沿用）。
- ①② 写入 `Session.append`、自定义 session 事件（T1 沿用）。

- 群搜索（G5 仍开放，沿用最近会话翻页）。
- 跨群话题、一条话题绑多群。
- 改 harness（侧栏树形原语、确认卡 session 事件族——缺什么记 gap，不 fork）。
- （v1.1）通讯录 / 多维表格 / 文件独立入口、未读数（R21：无数据源不造假）。

## 9. v1.1 增补：云之家工作台（已拍板 2026-08-17 下午）

> 缘起：用户对 R12 侧栏树提出三连反馈——「UI 要更精致」「群空间应有独立子页承载而非侧栏铺开」「群与对话之间要一层会话/话题列表」，随后确认导航范式为「IM 统一入口」；拍板后追加修正「话题应是对话中很轻的东西」——话题面从整面页签改为右侧抽屉（Slack 线程式）。可交互原型（Cursor canvas `group-room-three-column.canvas.tsx`）走查通过后拍板六项（§9.6）。本节是 R15–R21 的展开；与 v1.0 冲突处以本节为准（冲突点已在原条款内标注）。

### 9.1 三栏结构

```
① 官方侧栏（不动）                 ② 工作台中栏（域列表）           ③ 内容栏
   DSH 会话（含云之家 workspace 分组）   对话：会话列表（群+单聊混排）      时间线常驻 + 发进群 composer
   ┌ 侧栏脚「云之家」入口块 ┐            待办：任务列表（库切换器）          ┌ 话题抽屉（右侧轻栏，可关）┐
   │ 对话 / 待办 / 日程     │            日程：今日列表                    │ 列表态：话题卡         │
   │ 知识库 / 记忆          │            知识库：按库分组文档               │ 透镜态：锚点条+气泡+问助手│
   │ 机器人通道 · 状态行    │            记忆：vault 条目（标注本地）        └（header「话题 N」开关）─┘
   └──────────────────────┘                                              其余域 = 详情面（字段 + 跨域动作）
```

- 载体不变：入口块 = `sidebar.footer.action`（原树的槽位原地重画）；工作台 = 既有 `conversation.view` 子页内部自排两栏。不 fork harness。
- 对话域会话列表 = `im group recent`（原生混排群/单聊，按时间序）+「加载更多会话」翻页；单聊行点开即聊（R17），无话题抽屉。
- **话题抽屉是「对话中很轻的东西」**：时间线永远是主体、永不被顶走；抽屉固定窄栏（≈264px）、随手可关（×）；列表态 ⇄ 透镜态在抽屉内切换（‹ 返回）；抽屉底部「问助手」轻输入。反跳（L6）时抽屉不关——左时间线高亮定位、右透镜保持，两边同屏对照。
- 精致度基线（P1 验收对照）：同人连发合并（首条带头像名，后续缩进）、日期分隔线、自己 8/2/8/8 右气泡 / 他人 2/8/8/8 左气泡 / 助手左描边、行操作 hover 16px 文字链、助手产物卡（类型徽标 + 文件名 + 落库指引）、话题入口 = 气泡内嵌「N 条回复」chip（取代行尾文字链）。

### 9.2 联动规则 L1–L6（话题 × 会话列表）

合并发生在客户端：中栏把 recent 列表与 `ctx.yzjTopics` 快照按 groupId 拼接。`TopicRecord` 增加 `lastActivity` 时间戳（P0）；`status` 字段留 P3（此前徽标退化为话题总数点）。

| # | 规则 | 行为 |
|---|---|---|
| L1 | 上浮 | 群行时间与摘要 = max(最新群消息, 最新话题活动)；话题动态带「话题·标题」前缀 |
| L2 | 徽标分级 | accent 数字 = 待确认话题数（P0 可从 write-gate pending 推出）＞ 细点 = 有进行中 ＞ 全完成无标；**不是未读数** |
| L3 | 就地成话题 | 时间线「交给助手」→ 建话题并在右侧抽屉打开（时间线不被顶走）；该消息行操作立刻变「N 条回复」chip（幂等，二次点击 = 抽屉重开该话题） |
| L4 | 双入口一会话 | 话题在官方侧栏照常列出（不隐藏不复制）；两个入口进同一会话，默认投影不同（R19） |
| L5 | 交付回落 | 话题内「发进群」过确认卡后成为真实群消息：群行摘要回普通消息、话题降级、徽标随之降 |
| L6 | 全量反跳 | 话题内一切群消息引用可点、跳回时间线定位高亮：头部锚点条、过程中引用的群消息卡（记 msgId + 摘要快照）、交付回执「已发进群 · 查看群消息」；目标不在已加载窗口先 backfill 再定位。与内嵌 chip 构成双向闭环 |

群行点击**永远落时间线、抽屉不自动弹开**（拍板 #5）：落点可预测，话题动态靠 L1 前缀 + L2 徽标引导。

### 9.3 话题双投影（R19 展开）

- **IM 透镜**（群内话题抽屉）：气泡流、轻交互、锚点条、引用卡、回执；抽屉 header「原生会话 ↗」。
- **原生视图**（官方 conversation）：完整轨迹 / 工具卡 / 确认卡 / 全量 composer；头部锚点卡（回群房间）沿用。
- 两个投影读同一份 session 事件日志；跳转 = 官方 focus API，零新机制。

### 9.4 云之家 Host Workspace（R20 展开）

- 固定专属目录作为全部 yzj 会话的 `meta.cwd`（目录位置 = 实现决策，落地记 gap）；启动时 ensure「云之家」workspace（`ctx.workspaceRegistry`）并 attach 会话。
- 效果：官方侧栏原生按工作区分组，云之家会话不再混入编码工作区；此前传 `process.cwd()` 是缺陷，P0 修。
