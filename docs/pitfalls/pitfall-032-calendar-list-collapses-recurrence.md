# Pitfall 032 — `calendar event list` 跨天窗口只留循环日程的第一次

> 记录日期：2026-08-18 ｜ 解法更新：2026-08-19 ｜ 影响区域：`packages/tool-yzj/src/calendar.ts`、`packages/ui-yzj` `/yzj` `events` RPC、工作台日程月历

## 现象

工作台打开「日程」永远只看得到 **8 月 3 日** 的「测试日程」。点今天右侧是空的；agent 调 `yzj_calendar_event_list` 查整月也只吐这一条。云之家客户端同一天其实有会。

单测绿：面板把 `2026-08-01`–`2026-08-31` 原样交给 CLI，假 bridge 回什么就画什么，jsdom 看不到循环展开。

## 根因

面板 / 工具一次查整月。`yzj-cli calendar event list`（及背后的云之家接口）对**跨天窗口**不展开循环实例：窗口里同系列只留**最早的一次**。文档写「超过 30 天自动分片并去重」，但 **2 天窗口已经丢实例**。宽窗口会带回该区间里最早有会的那天（有时还带上后面几天），不能当成完整列表。

| 窗口 | 实测 |
|---|---|
| `--start 2026-08-18 --end 2026-08-18` | 当天 10:00 那次（id `…a0cd`） |
| `--start 2026-08-01 --end 2026-08-31` | 只有 8 月 3 日那次（id `…a030`） |
| `--start 2026-08-17 --end 2026-08-18` | 只有 17 日；18 日同系列被丢掉 |
| `--start 2026-08-04 --end 2026-08-31` | 4 日两次（10:00 / 16:00）；后面的循环实例没有 |
| `--start 2026-08-28 --end 2026-08-31` | 空（后缀可以一次停掉） |

同一系列每天的 `id` 不同，`startDate` 是 epoch-ms，解析没有错。错在查询粒度。

v1.6「打开日程落在今天」只改了选中日，没改拉取窗口。

## 解法

host 侧 **按 7 天切条带，条带内快慢指针**：

- 慢指针 `lo`：下一块还没确认的日期。
- 快窗口：`calendar event list --start lo --end stripeEnd`。空结果 ⇒ 这条带剩下的天都空，直接停。
- 只采信返回里**最早那天**的事件（同一 peek 里更晚的日子可能是折叠残片），然后 `lo = 最早日 + 1` 再探。
- 条带之间并发 6。空月份大约 5 次 peek；密集会退化成「有会的天数 + 空后缀」次，而不是 31 天全打。

超过 366 天拒绝。面板 RPC 与 `yzj_calendar_event_list` 共用 `collectCalendarEvents`。

不按整周结果当真：同一周里 17+18 仍会被折叠，所以只能信最早日。

## 回归覆盖

- `packages/tool-yzj/tests/calendar-range.spec.ts`：条带切分、后缀空则停、折叠假 CLI 仍能拿到后一天、超长拒绝。
- `packages/ui-yzj/tests/rpc.node.spec.ts`：2 日窗口先 peek `17–18` 再 `18–18`。
- `packages/tool-yzj/tests/tools.spec.ts`（已登录才跑）：整月结果必须覆盖「今天」单日查出的每条 id。

## 给 yzj-cli 开发者的缺陷说明（可整段转发）

**标题：** `calendar event list` 跨天查询会丢掉循环日程的后续实例

**环境：** `@yunzhijia/cli`（`yzj-cli calendar event list`），个人授权，已登录。云之家客户端同一日历能看到全部场次。

**复现（把日期换成任意一个「每天/每个工作日」循环会所在的月份）：**

```bash
# 单日：能拿到当天那一次
yzj-cli calendar event list --start 2026-08-18 --end 2026-08-18

# 整月：只剩这个系列在窗口里的第一次（本例是 8 月 3 日）
yzj-cli calendar event list --start 2026-08-01 --end 2026-08-31

# 两天已经丢：17 日在、18 日同系列不在
yzj-cli calendar event list --start 2026-08-17 --end 2026-08-18

# 从第一次之后再查：能拿到「新窗口」里的第一次，说明不是数据没了，是窗口折叠
yzj-cli calendar event list --start 2026-08-04 --end 2026-08-31
```

**期望：** `--start/--end` 覆盖到的每一场都返回，循环会的每一天一次各有自己的 `id` + `startDate`（和官方日历、以及单日查询一致）。超过 30 天如果要分片，合并时应按 **实例 id** 去重，不要按系列 / 标题去重。

**实际：** 跨天窗口只稳定返回该区间里**最早有会的那天**（同系列后面的实例被吃掉）。整月查询因此永远钉在第一次。文档写「超过 30 天自动分片并去重」，但 2 天窗口已经丢，所以不只是 30 天分片的问题。

**字段观察：** 各场 `id` 不同（例如 `…a030` vs `…a0cd`），`startDate`/`endDate` 是 epoch-ms，单日查询是对的。缺的是跨天展开，或展开后被按系列合并掉了。

**影响：** 所有按周/按月调 `calendar event list` 的调用方（日历月视图、agenda、「本周有什么会」）都会漏会。调用方现在只能单日查或自己做后缀扫描。

**建议（任选）：**

1. list 默认按实例展开（和官方日历一致）；需要系列去重时加显式开关，例如 `--unique-series`。
2. 若上游接口有分页 / `hasMore` / `nextToken`，CLI 应翻完再输出，不要只回第一页。
3. 文档改成明确写：跨天窗口不保证返回全部实例；并给出推荐的按日或游标用法。
